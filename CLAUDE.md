# TW-PKM-Fields — contexte projet pour Claude

> **Avant toute tâche sur ce plugin, consulter d'abord le `CLAUDE.md` du workspace** (`../CLAUDE.md`, dont § Suite pkm) et ses `guides/` : outillage de dev commun (pnpm, `dev.cjs`/HMR, Ctrl+C, git push), pièges PowerShell/Windows, `publishFilter`, conventions de nommage/i18n, symlink, test de rendu hors navigateur. Ci-dessous : uniquement le spécifique à TW-PKM-Fields.

## Ce que c'est
Interface de la suite pkm (`$:/plugins/nikorion/pkm-fields`) : place dans le template d'édition — et dans les colonnes de TW-Dynamic-Table s'il est installé — les champs définis par le schéma (`../TW-PKM-Schema`, requis — `dependents` du `plugin.info`). **Ne connaît aucun champ par son nom** : le contrôle est choisi par le `kind` du champ (API `pkm-*`) — `vocab` → liste déroulante ou radio, `vocab-list` → une case par valeur, `value` → saisie + menu des valeurs utilisées, `list` → pastilles + saisie, `date` → saisie date du navigateur. Aucun JS. **Aucune surcharge de tiddler core** — sections `$:/tags/EditTemplate` placées par `list-before`/`list-after`.

Docs (règle des trois publics : `../CLAUDE.md` § Conventions) : le readme du plugin décrit le comportement de l'éditeur ; sens des champs, vocabulaires, icônes, libellés = schéma, jamais ici. **Avant de chercher quel fichier toucher, ou d'ajouter un champ ou une nature (`kind`) → lire `README.md`** (§ Source layout, § Extending) — ne pas agir de mémoire.

## Couches (refonte 2026-09-30)
| Dossier | Rôle | Appelle |
|---|---|---|
| `controls/` | contrôles nus par `kind` (`nk-vocab-select`/`-radios`, `nk-vocab-checkboxes`, `nk-value-input`, `nk-list-input`, `nk-date-input`) : écrivent le champ de `currentTiddler`, sans libellé ni corbeille ; chaînes, actions (`nk-field-changed` : vide → suppression, `icon` suit `role`), `nk-stale-hint` | API `pkm-*` seule |
| `editor/` | `nk-field`/`nk-field-control` : habillage éditeur (libellé, corbeille, cadre rouge) + sections EditTemplate | `controls/` |
| `dyntable/` | cellules : valeur en lecture, contrôle nu en édition (`currentTiddler` = `currentRecord`) | `controls/` |

- **Dépendance à sens unique** : `controls/` n'appelle jamais `editor/` ni `dyntable/`, qui ne s'appellent pas entre eux. Un besoin propre à un emplacement = paramètre d'apparence du contrôle (`class`, `tabindex`, `emptyText`, `sizerText`) ou CSS de la couche qui place (ex. largeur mini en cellule : `dyntable/styles.tid`), jamais un drapeau « en cellule ». Ne jamais recopier un contrôle dans une couche d'emplacement (la copie de `dyntable/` avait divergé : l'`icon` ne suivait pas le rôle édité en tableau).
- **Pas de plugin séparé pour `controls/`** (décision 2026-09-30) : on découpe en plugins ce qui s'installe séparément. Le sortir en plugin seulement le jour où un autre plugin a besoin des contrôles sans l'éditeur ; la règle ci-dessus rend ce déplacement mécanique.

## Spécificités
- **Chaînes de l'éditeur** : `nk-field-text(field,key)` = `Fields/<champ>/<clé>` si le champ a sa formulation propre, sinon `Fields/<clé>` générique ; placeholder = le sien sinon le libellé en minuscules. Ne pas ajouter de chaîne par champ quand la générique se lit bien (`Delete/Hint`, `Prompt` : génériques seulement).
- **Cadre rouge (`nk-stale`)** : `nk-field` masque un champ dont l'`applies-filter` (schéma) rejette le tiddler, **sauf s'il porte une valeur** → affiché `stale="yes"`, cadre rouge, infobulle `Fields/Stale/Prefix` + pluriel du rôle (`pkm-vocab-plural`, `role`) + `Fields/Stale/Suffix` joints par une espace (un `.multids` trim les bords). Phrases propres à `status` : `Fields/status/Stale/Hint` et `…/Stale/NoRole/Hint` (sans rôle) — **à tenir en phase avec l'`applies-filter` de `status`** dans le schéma. **Le rôle est encadré aussi** tant qu'un autre champ est stale (`nk-conflict-hint`, info-bulle `Fields/role/Conflict/Hint` ou `…/NoRole/Hint` listant les libellés) : seul un champ ayant sa chaîne `Conflict/Hint` y participe, aucun nom en dur ; éditeur et cellules testent tous deux `nk-flag-hint` (stale ou conflit). Pièges : `:map` (même `:map:flat`) change une run vide en `""` → garder `:and` + `!match[]` ; `:map` s'applique à **tous** les résultats précédents du run (d'où les calculs à part dans un `$let`) ; `:and[function…]` ne se déclenche pas comme garde sur une entrée vide.
- **Un vocabulaire à `blank-value` doit être en radio** (`maturity`, `lifecycle`, `status`) : la liste déroulante ne gère pas la valeur vide (elle stockerait son slug).
- **Radio** (`controls.multids`, `…/control/<champ>: radio`) : la valeur vide du vocabulaire (`pkm-vocab-blank`) porte la valeur `""` — cochée quand le champ est vide, la choisir le vide ; sans icône elle est en italique (`nk-vocab-none`). Ne pas réintroduire de valeur par défaut stockée.
- **Chaque `.nk-extra-row` est une ligne pleine largeur**, placée par le seul `list-before`/`list-after` ; la CSS ne dispose que l'intérieur d'une ligne. Ne pas réapparier avec une ligne du core via une grille : essayé, abandonné — ajouter un tag décalait `role` latéralement, et un champ liste à l'étroit empilait ses pastilles au-dessus de sa saisie.
- **Ne pas réintroduire de surcharge core.** Écarté deux fois (copies de `EditTemplate/type` et `…/tags`) : fige l'ancienne version à la montée de TW, collisionne avec tout plugin touchant la même ligne.
- **Pas de `tag-picker` pour les saisies, et ne pas y revenir** : il code en dur le placeholder des tags et réutilise `newTagNameTiddler` (un seul pour tout le formulaire) → saisies partagées, et Ctrl+Entrée ajouterait le texte en cours comme **tag**. Pilotage direct de `keyboard-driven-input`, tiddlers d'état dérivés du nom du champ (`$:/temp/New<Champ>Value*` liste, `$:/temp/<champ>/*` valeur unique).
- **Filtres de complétion (`controls/search-filters.tid`) : variable `pfField`, jamais `field`** — `keyboard-driven-input` a son propre paramètre `field` (champ du tiddler de saisie) qui masquerait le nôtre là où les filtres s'évaluent. Ils dédupliquent explicitement (`each:value[]`, `each:list-item`) : ne pas simplifier (piège de déduplication, `../CLAUDE.md`).
- **Après avoir écrit un champ que la saisie affiche, poser `refreshTitle` à `yes`** : un `$edit-text` ne touche pas un élément qui a le focus — sans ça la saisie garde le texte tapé.
- **`<$select default="">` obligatoire** (vocabulaire en liste déroulante, aujourd'hui `role`, `epistemology`, `regime`) : sans lui, `selectedIndex` = -1 et le contrôle s'affiche vide. La 1re option vide (`hidden` + `disabled`) doit rester : sans elle, un tiddler sans valeur afficherait la 1re valeur comme choisie.
- **Largeur des saisies = placeholder.** Valeur unique : `--nk-input-chars` (longueur, min 12). Champ `list` : copie cachée du texte (`nk-input-sizer`) dans la même case de grille que la saisie, qui prend sa largeur réelle (exacte dans tout navigateur, pas de `ch` ni de `field-sizing`) ; texte = placeholder le plus long des champs `list` dans l'éditeur (alignement, `nk-list-longest-placeholder`), le sien par défaut (cellule de tableau : `sizerText` non fourni). Saisie `width: 0; min-width: 100%` : sinon sa largeur par défaut (~20 car.) dimensionne la case.
- **Un libellé s'aligne sur son contrôle en `align-items: baseline`**, jamais par `padding-top` : la 1re ligne d'un encadré de champ liste est tantôt une pastille, tantôt la saisie (7 px d'écart).
- **`project`/`epistemology`/`regime`/`deviation`/`disciplines` sur une ligne, `technology`/`equipment` sur une autre** — jamais ensemble : un champ liste prend toute la largeur qu'on lui donne. Ranger un champ de plus dans une de ces lignes plutôt qu'en créer une troisième.
- **`$:/config/SyncFilter` du wiki de dev** : exclure aussi les shadows livrés hors du namespace du plugin (`$:/config/EditTemplateFields/Visibility/`, `$:/config/nikorion/pkm-fields/`) et ceux du schéma — sinon un push HMR les écrit en vrais tiddlers sous `wiki/tiddlers/system/`, copies figées qui masquent ensuite les plugins. S'ils réapparaissent : les supprimer, vérifier le filtre.
- **Ne jamais conseiller un rechargement d'onglet pour voir une modif** (il annule le HMR) ; regarder l'onglet ouvert, ou redémarrer TW (`touch src/pkm-fields/plugin.info`) avant de recharger. Une modif du schéma n'est pas poussée par ce wiki.
- **Aucune couche de compatibilité** (`compat/` retiré 2026-09-28, passage kms → pkm et `base-fields` → `pkm-fields`, choix utilisateur) : ni alias `bf-vocab-*`/`kms-*`, ni anciens titres d'icône `…/base-fields/vocab/icons/…`, ni ancien nom `base-fields`/préfixe `bf-` ; `nk-sync-role-icon` ne traite comme « à nous » que le préfixe `…/pkm-schema/icons/`. Ne pas en réintroduire.
- **Colonnes de tableau (`dyntable/`)** : branchées sur les tags de TW-Dynamic-Table (`$:/tags/nk-dyntable/BodyTemplate` + `nk-dyntable-column-filter` par `kind`, `…/Procedure`, `…/ColumnLabelFilter`, `…/ColumnHintFilter`, `…/ColumnNoCalcFilter` — `column-no-calc.tid` : `kind` vocab/vocab-list = codes, jamais additionnés en pied sans `@`, `…/RowClassFilter`), inertes sans lui ; Dynamic Table ne connaît pas le schéma et ne doit pas le connaître. **Avant de toucher `dyntable/` → lire `../TW-Dynamic-Table/README.md` § Extending from another plugin** (variables, chaînes et classes reçues = contrat). Les procédures d'édition `nk-pkm-*` appellent les contrôles nus de `controls/`, avec une `transclusion` unique par cellule pour `value`/`list` (sinon toutes les lignes partagent la saisie). Cadre rouge et info-bulles de valeur : `pkm-is-stale`, `pkm-vocab-tooltip`, `pkm-actual-value` (schéma) + `nk-stale-hint` (phrase de l'éditeur), partagés éditeur/cellules — ne pas les redupliquer ; dans une cellule encadrée, pas d'info-bulle intérieure (`nk-pkm-fresh`, `pkm-pill tooltip="no"`), comme dans l'éditeur. Une nouvelle nature (`kind`) = aussi un `dyntable/body/<kind>.tid`.
