# TW-Base-Fields — contexte projet pour Claude

> **Avant toute tâche sur ce plugin, consulter d'abord le `CLAUDE.md` du workspace** (`../CLAUDE.md`, dont § Suite kms) et ses `guides/` : outillage de dev commun (pnpm, `dev.cjs`/HMR, Ctrl+C, git push), pièges PowerShell/Windows, `publishFilter`, conventions de nommage/i18n, symlink, test de rendu hors navigateur. Ci-dessous : uniquement le spécifique à TW-Base-Fields.

## Ce que c'est
Éditeur de la suite kms (`$:/plugins/nikorion/base-fields`) : place dans le template d'édition les champs définis par l'ontologie (`../TW-KMS-Ontology`, requise — `dependents` du `plugin.info`). **Ne connaît aucun champ par son nom** : `bf-field` lit le `kind` du champ via l'API `kms-*` et dessine le contrôle — `vocab` → liste déroulante ou radio, `vocab-list` → une case par valeur, `value` → saisie + menu des valeurs utilisées, `list` → pastilles + saisie. Aucun JS. **Aucune surcharge de tiddler core** — sections `$:/tags/EditTemplate` placées par `list-before`/`list-after`.

Trois docs, trois publics, **zéro duplication entre eux** : readme du plugin (`src/base-fields/language/<lang>/readme.tid`) = utilisateur du wiki (comportement de l'éditeur) ; `README.md` = développeur (installation dev, structure, fonctionnement, extension) ; ce fichier = instructions au modèle. Sens des champs, vocabulaires, icônes, libellés = ontologie, jamais ici. **Avant de chercher quel fichier toucher, ou d'ajouter un champ ou une nature (`kind`) → lire `README.md`** (§ Source layout, § Extending) — ne pas agir de mémoire. Toute info nouvelle va dans le seul document de son public.

## Les 3 lignes
| Ligne (classe) | Champs par défaut (`rows.multids`, config `$:/config/nikorion/base-fields/row/<ligne>`) | Section |
|---|---|---|
| `.bf-pre-tags-extras` | `project`, `epistemology`, `disciplines` | `discipline-fields.tid` (`list-before: …/EditTemplate/tags`) |
| `.bf-post-tags-extras` | `technology`, `equipment`, puis tout champ libre qu'aucune ligne ne nomme | `extra-fields.tid` (`list-after: …/EditTemplate/tags`) |
| `.bf-type-extras` | `role`, `maturity`, `lifecycle`, `needs`, `status`, puis tout champ à vocabulaire non placé | `vocab-fields.tid` (`list-after: …/EditTemplate/type`) |

Ordre voulu (2026-09-25) : `project`, `epistemology`, `disciplines`, //tags (core)//, `technology`, `equipment` — d'où `discipline-fields.tid` **avant** les tags et `extra-fields.tid` **après**, malgré leurs noms de fichier historiques (gardés pour ne pas casser les renvois).

Contrôle libellé = `<span class="bf-edit-field">` : `<em class="tc-edit tc-small-gap-right">` (format `Fields/Prompt`, `$label$` ← libellé de l'ontologie ; infobulle = description de l'ontologie, **sauf** en cadre rouge : un `title` intérieur, même vide, masquerait celui du cadre), le contrôle, `bf-delete-field-button`. Champ liste = `<span class="bf-list-field">`, sans libellé visible (le placeholder en tient lieu).

## Spécificités
- **Chaînes de l'éditeur** : `bf-field-text(field,key)` = `Fields/<champ>/<clé>` si le champ a sa formulation propre, sinon `Fields/<clé>` générique ; placeholder = le sien sinon le libellé en minuscules. Ne pas ajouter de chaîne par champ quand la générique se lit bien (`Delete/Hint`, `Prompt` : génériques seulement).
- **Cadre rouge (`bf-stale`)** : `bf-field` masque un champ dont l'`applies-filter` (ontologie) rejette le tiddler, **sauf s'il porte une valeur** → affiché `stale="yes"`, cadre rouge, infobulle `Fields/Stale/Prefix` + pluriel du rôle (`kms-vocab-plural`, `role`) + `Fields/Stale/Suffix` joints par une espace (un `.multids` trim les bords). Phrases propres à `status` : `Fields/status/Stale/Hint` et `…/Stale/NoRole/Hint` (sans rôle) — **à tenir en phase avec l'`applies-filter` de `status`** dans l'ontologie. Pièges : `:map` s'applique à **tous** les résultats précédents du run (d'où les calculs à part dans un `$let`) ; `:and[function…]` ne se déclenche pas comme garde sur une entrée vide.
- **Radio** (`controls.multids`, `…/control/<champ>: radio`) : la valeur vide du vocabulaire (`kms-vocab-blank`) porte la valeur `""` — cochée quand le champ est vide, la choisir le vide ; sans icône elle est en italique (`bf-vocab-none`). Ne pas réintroduire de valeur par défaut stockée.
- **Chaque `.bf-extra-row` est une ligne pleine largeur**, placée par le seul `list-before`/`list-after` ; la CSS ne dispose que l'intérieur d'une ligne. Ne pas réapparier avec une ligne du core via une grille : essayé, abandonné — ajouter un tag décalait `role` latéralement, et un champ liste à l'étroit empilait ses pastilles au-dessus de sa saisie.
- **Ne pas réintroduire de surcharge core.** Écarté deux fois (copies de `EditTemplate/type` et `…/tags`) : fige l'ancienne version à la montée de TW, collisionne avec tout plugin touchant la même ligne.
- **Pas de `tag-picker` pour les saisies, et ne pas y revenir** : il code en dur le placeholder des tags et réutilise `newTagNameTiddler` (un seul pour tout le formulaire) → saisies partagées, et Ctrl+Entrée ajouterait le texte en cours comme **tag**. Pilotage direct de `keyboard-driven-input`, tiddlers d'état dérivés du nom du champ (`$:/temp/New<Champ>Value*` liste, `$:/temp/<champ>/*` valeur unique).
- **Filtres de complétion (`search-filters.tid`) : variable `bfField`, jamais `field`** — `keyboard-driven-input` a son propre paramètre `field` (champ du tiddler de saisie) qui masquerait le nôtre là où les filtres s'évaluent. Ils dédupliquent explicitement (`each:value[]`, `each:list-item`) : ne pas simplifier (piège de déduplication, `../CLAUDE.md`).
- **Après avoir écrit un champ que la saisie affiche, poser `refreshTitle` à `yes`** : un `$edit-text` ne touche pas un élément qui a le focus — sans ça la saisie garde le texte tapé.
- **`<$select default="">` obligatoire** (vocabulaire en liste déroulante, aujourd'hui `role`) : sans lui, `selectedIndex` = -1 et le contrôle s'affiche vide. La 1re option vide (`hidden` + `disabled`) doit rester : sans elle, un tiddler sans valeur afficherait la 1re valeur comme choisie.
- **Largeur des saisies = longueur du placeholder** (`--bf-input-chars`) : valeur unique = son placeholder (min 12) ; les champs `list` partagent le max des leurs (`bf-list-placeholder-chars`, calculé sur l'ontologie).
- **Un libellé s'aligne sur son contrôle en `align-items: baseline`**, jamais par `padding-top` : la 1re ligne d'un encadré de champ liste est tantôt une pastille, tantôt la saisie (7 px d'écart).
- **`project`/`epistemology`/`disciplines` sur une ligne, `technology`/`equipment` sur une autre** — jamais ensemble : un champ liste prend toute la largeur qu'on lui donne. Ranger un champ de plus dans une de ces lignes plutôt qu'en créer une troisième.
- **`$:/config/SyncFilter` du wiki de dev** : exclure aussi les shadows livrés hors du namespace du plugin (`$:/config/EditTemplateFields/Visibility/`, `$:/config/nikorion/base-fields/`) et ceux de l'ontologie — sinon un push HMR les écrit en vrais tiddlers sous `wiki/tiddlers/system/`, copies figées qui masquent ensuite les plugins. S'ils réapparaissent : les supprimer, vérifier le filtre.
- **Ne jamais conseiller un rechargement d'onglet pour voir une modif** (il annule le HMR) ; regarder l'onglet ouvert, ou redémarrer TW (`touch src/base-fields/plugin.info`) avant de recharger. Une modif de l'ontologie n'est pas poussée par ce wiki.
- **`compat/`** = dépréciés depuis 0.4.0, à retirer plus tard : alias `bf-vocab-*` → `kms-vocab-*`, et anciens titres d'icône `…/base-fields/vocab/icons/…` (déjà stockés dans le champ `icon` de tiddlers). `bf-sync-role-icon` traite les deux préfixes comme « à nous ».
- **TW-Dynamic-Table appelle `bf-list-value-field(field)`** (`../TW-Dynamic-Table/src/dyntable/procedures/dt-kms.tid`, avec `transclusion` unique par cellule) : **avant d'en changer la signature → répercuter là-bas**, même tâche.
